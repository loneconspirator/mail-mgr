       ```typescript
       /**
        * FM-002: chokepoint wrapping every public IMAP op.
        * (a) refuses to issue if flow missing or flow.usable is false (and
        *     force-closes so reconnect runs),
        * (b) bounds the inner imapflow call with withTimeout,
        * (c) on timeout, force-closes so reconnect runs.
        * Caller-side errors (NoConnection, server errors) propagate without
        * forcing close — handleClose is only invoked on wedge-shaped failures.
        */
       private async guardedOp<T>(
         label: string,
         op: (flow: ImapFlowLike) => Promise<T>,
         timeoutMs: number,
       ): Promise<T> {
         if (!this.flow) throw new Error('Not connected');
         if (!this.flow.usable) {
           this.handleClose();
           throw new Error(`IMAP ${label}: connection not usable`);
         }
         // Capture this.flow into a local `flow` const before passing to op —
         // protects the closure if a concurrent handleClose nulls the reference
         // between the usable check and the inner call.
         const flow = this.flow;
         try {
           return await withTimeout(op(flow), timeoutMs, `IMAP ${label}`);
         } catch (err) {
           if (err instanceof Error && /timed out/i.test(err.message)) {
             this.handleClose();
           }
           throw err;
         }
       }
       ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ImapClient ↔ remote IMAP server (TLS) | Authenticated socket; pre-fix a wedged path is undetected silent failure |
| Web request handler ↔ ImapClient | Internal — no untrusted input — but a wedge propagates as request hang |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | D (DoS via stuck request) | Fastify request handlers awaiting ImapClient | accept (this plan) | Foundation only — Plan 02 wires guardedOp through every public op, which converts hang → fast error. This plan provides the chokepoint. |
| T-34-02 | I (Information disclosure / silent data loss) | IX-001 arrival path on ImapClient | mitigate | cleanupFlow now calls flow.close() so in-flight rejected promises propagate to wedged callers; combined with Plan 02's per-op guarding, IX-001 will fail fast on a wedge instead of silently halting. T-34-02 is high — must land in this phase (this plan delivers the close() fix; Plan 02 delivers the guarding). |
| T-34-03 | D (resource leak via orphaned imapflow) | ImapClient.cleanupFlow | mitigate | this.flow.close() now invoked before nulling the reference, so imapflow drains its requestTagMap and pending locks. Memory of the orphaned instance is GC'd once awaiters drop their references. |

`block_on: high` — T-34-02's mitigation in this plan (cleanupFlow.close()) is required for Plan 02 to be observable in tests. No release on Plan 01 alone, but it must precede Plan 02.
