# Milestone v0.8: Action Folder Safety Hardening & FM-002 Generalization

**Status:** ✅ SHIPPED 2026-05-06
**Phases:** 33-34
**Total Plans:** 5
**Total Tasks:** 11
**Timeline:** 2026-04-24 → 2026-05-05 (12 days)

## Overview

Incident-driven hardening of the action-folder pipeline (prevent mass erroneous rule creation from Block/VIP floods and eliminate wasteful sentinel-only polling) plus generalization of the FM-002 wedge-detection contract from IDLE+listFolders to the entire ImapClient public surface. Every public ImapClient operation now routes through a `guardedOp` chokepoint with per-op timeout buckets; `cleanupFlow` drains in-flight imapflow promises; `flow.connect()` and the initial `mailboxOpen` are bounded; `idleTimeout` default drops 300s→90s for 3.3× faster wedge detection; FM-002/MOD-0002 specs widened to match.

## Milestone Summary

**Decimal Phases:** None.

**Key Decisions:**

- `guardedOp` chokepoint extracted from inline FM-002 pattern — every public IMAP op funnels through a single wedge-detection seam.
- `imapflow.close()` is the in-flight cancellation seam — do not roll AbortController plumbing.
- Clustered op-class timeout buckets (CONNECT/LOCK/WRITE/BULK_FETCH) instead of per-op constants.
- FM-002 file NOT renamed — title-frontmatter rewrite sufficient; renaming would invalidate paths baked into IX-001/MOD-0002/external linkers.
- FM-002 Required behavior enumerates the full guarded surface inline (not a pointer to MOD-0002) — spec stands alone.
- `pendingActivities` accumulator for action-folder logging — defer log entries until after move succeeds.
- Diagnostic logging goes to pino only (not activity log) — ops debugging, not user audit trail.

**Issues Resolved:**

- Action-folder pre-move activity logging (false-positive success entries on move failure).
- Duplicate-path fall-through to create branch (potential double-move).
- Wasteful `fetchAllMessages` polls on sentinel-only folders.
- Wedged IMAP connection silent failures across the entire public ImapClient surface.
- `flow.connect()` and initial `mailboxOpen` could hang indefinitely.
- In-flight imapflow promises orphaned on `handleClose`.
- 4 doc inconsistencies in 34-02 timeout buckets (LIST vs WRITE, WRITE vs BULK_FETCH) — fixed in audit-gap-close commit.
- Test gap: `sentinelCount === rawMessages.length` skip-retry branch in poller had no unit coverage — fixed in audit-gap-close commit.

**Issues Deferred:**

- Private `poll()` fallback method (used when IDLE unsupported) issues bare `flow.noop()` without timeout wrapper — pre-existing, not introduced by v0.8. Tracked in backlog if non-IDLE servers become a target.

**Technical Debt Incurred:**

- Wedge detection latency is up to 120s (90s idleTimeout + 30s NOOP timeout), not 90s — R5 satisfied as written; framing in SUMMARY is informational.

**Audit Status:** PASSED (12/12 requirements, 4/4 integration flows, 4/4 E2E flows, both phases Nyquist-compliant). All gaps closed in same session.
