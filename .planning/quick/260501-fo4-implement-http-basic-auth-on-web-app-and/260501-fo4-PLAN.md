<objective>
Add HTTP BASIC auth in front of all mail-mgr web UI and API routes (Fastify), sourced from `WEB_AUTH_USER` / `WEB_AUTH_PASS` env vars, with an unauthenticated `/healthz` endpoint for container probes.

Purpose: Service currently exposes mail content, rule config, and action triggers on the LAN with zero auth. Even on Soma, this is too permissive — and inevitably something LAN-only ends up reachable beyond the LAN.

Output:
- `src/web/auth.ts` — Fastify onRequest hook factory with constant-time compare
- `src/web/routes/health.ts` — unauthenticated `/healthz` route
- `src/web/server.ts` — wires health route + auth hook (in correct order)
- `test/unit/web/auth.test.ts` — unit tests covering happy + sad paths
- README + docker-compose updated with new env vars
- Dockerfile gets a `HEALTHCHECK` directive that hits `/healthz`

Decision (planner): **fail-closed** on missing env vars. This is security middleware; silent skip is exactly the kind of footgun this todo is meant to fix. Startup error is loud and unambiguous.
</objective>

    1. Create `src/web/auth.ts`:
       - Export `const HEALTH_PATH = '/healthz'`
       - Export `function basicAuthHook(user: string, pass: string)` returning a Fastify `onRequest` async hook `(req, reply) => Promise<void>`
       - Hook logic:
         a. If `req.url === HEALTH_PATH` (or starts with `${HEALTH_PATH}?` for query strings) → return immediately, no auth
         b. Read `req.headers.authorization`. If missing or doesn't start with `Basic ` (case-insensitive) → call `sendUnauthorized(reply)` and return
         c. Decode the base64 portion. Wrap in try/catch; on any error → `sendUnauthorized(reply)` and return
         d. Split decoded value on the FIRST `:` (use `indexOf` + slice — DO NOT use `split(':')` because passwords may contain colons). If no `:` found → `sendUnauthorized(reply)`
         e. Compare username with `===` (cheap, low-risk leak — username isn't secret). Compare password using `timingSafeEqual`:
            - Convert both expected pass and provided pass to Buffers
            - If `Buffer.byteLength` differs → still call `timingSafeEqual` against a same-length dummy buffer of the expected pass, then return false. This avoids leaking length AND avoids the throw. (Implementation hint: always do `timingSafeEqual(expected, provided.length === expected.length ? provided : Buffer.alloc(expected.length))` and AND the result with `provided.length === expected.length`.)
         f. On mismatch → `sendUnauthorized(reply)`
       - Helper `sendUnauthorized(reply)`:
         - `reply.header('WWW-Authenticate', 'Basic realm="mail-mgr"')`
         - `reply.code(401).send({ error: 'Unauthorized' })`
       - Export `function readAuthCredsOrThrow(): { user: string; pass: string }` that reads `process.env.WEB_AUTH_USER` and `WEB_AUTH_PASS`, throws an `Error` with message `"WEB_AUTH_USER and WEB_AUTH_PASS must both be set; refusing to start without auth"` if either is empty/missing.
